## Inconsistencies found in the source data

1. **Duplicate deck-R file name.** `e7_R_L2_lev0_VG1.25_tox20_NA1e+16_hw0.5_ov0_sg0_dpsi0.json` exists in both `results/phase3/C7/dev/` and `results/phase3/C7/realism/`. The bytes differ: the dev copy carries a DEVSIM cross-check and different timestamps. The network values are identical. The `realism` copy is canonical, and the dev copy is recorded as a cross path; its DEVSIM `G_E` and `G_M` agree with the source-side reference to −2.8e-7 and +2.5e-7.
2. **Duplicate finite-bias files.** Six (L, V_G) groups have alias files, `*_VD0p1_5_20mV.json`, `*_VD0p1mV.json` and `*_VD1_5_20mV.json`, that repeat V_D points of the base file. All repeated values agree exactly (maximum relative difference in I_drain = 0). They are merged by V_D, and every file is listed as a source.
3. **The independent-FV "bracket" is not a bracket.** `fd2d_indep.py` reports `dL_slice`/`dL_rows` as trapezoid integrals of n. They are not exact bounds of its own Scharfetter–Gummel network: the FV network ΔL exceeds its own "slice" value at 0.621433 V (45.249 vs 45.157 nm) and at 0.7835 V (47.394 vs 47.274 nm). A likely cause, which I have *not* verified, is the logarithmic-mean SG edge weight versus the arithmetic quadrature. These fields are exported as informational only, never as a bracket.
4. **Bracket scope.** The FV ΔL lies outside the DEVSIM-mesh bracket at 2 of 3 A-W states while agreeing with the reference within 0.16%. The scorer therefore applies the bracket to same-mesh submissions only (a test covers this). This matches the correction already recorded in plan v2.
5. **Pre-existing test side effect.** The combined regression suite writes untracked artefacts: `semiconductor_sim/results/_test_stage/` and `semiconductor_sim/results/golden/_test_common_npz.npz`. They were deleted after each run and are not committed.

## Questions for WP3 (deck conventions an external code must match)

1. **Body contact.** The decks impose ψ = ψ_b0 at y = 1.2 µm with *zero electron flux*. A standard ohmic body contact would also fix φ_n = 0 there, adding a drain-to-body electron path to the zero-bias network. In deep subthreshold the channel conductance itself is about 1e-12 S/cm, so this path may not be negligible. WP3 must either prescribe an electron-blocking bottom boundary or quantify the substrate path.
2. **Holes.** The decks do not solve holes. A code that solves both carriers adds a hole network between source and drain. It is presumably negligible because p ≈ 1 cm⁻³ in the n⁺ wells, but it must be bounded, or the submission must report the electron current only.
3. **Gate convention.** For V_FB = 0 with ψ referenced to the intrinsic level, an external code must set the gate work function equal to the substrate work function. WP3 should state this in work-function terms.
4. **Target ψ̂.** The C10 definition is ψ̂ = (ψ_s,∞ − ψ_b0)/V_T. It is set by the long-channel 1-D MOS problem and does not depend on the source/drain deck, so the A-W V_G values (0.488174 / 0.621433 / 0.7835 V for N_A = 1e18 cm⁻³, t_ox = 2 nm) give ψ̂ = 12 / 16 / 21 in deck R as well. The same three V_G values give ψ̂ = 12 / 16 / 21 for the N_A = 1e16 cm⁻³, t_ox = 20 nm device in C10.
5. **Independent path for deck R.** `phase3/c11/fd2d_indep.py` supports deck W only, with Dirichlet junction faces. Extending it to resolved wells with ohmic far-edge contacts is a prerequisite for H1 in WP2.
